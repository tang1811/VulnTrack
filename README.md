# EEC VulnTrack — ระบบติดตามและรายงานช่องโหว่ทางเทคนิค

โครงงานรายวิชา ICT43467 · วิทยาลัยเทคโนโลยีแหลมฉบัง EEC

เว็บไซต์ศูนย์กลางสำหรับรวบรวม แสดงผล และติดตามสถานะการแก้ไขช่องโหว่ (CVE) ของคอมพิวเตอร์และเซิร์ฟเวอร์ภายในวิทยาลัย

**เทคโนโลยี:** Python 3.12+ · Django 5.2 LTS · MySQL 8 (หรือ SQLite สำหรับทดลอง) · Chart.js 4

| ส่วน | ใช้อะไร |
|---|---|
| Backend | Python 3.12+ / Django 5.2 (ORM, ฟอร์ม, session login, CSRF) |
| Frontend | Django Templates (เรนเดอร์ฝั่งเซิร์ฟเวอร์) + HTML5 + CSS ที่เขียนเอง + JavaScript ล้วน (vanilla) + Chart.js 4 |
| ฐานข้อมูล | MySQL 8 ผ่าน PyMySQL (`DB_ENGINE=mysql` ใน `.env`) หรือ SQLite สำหรับทดลองบนเครื่อง |
| รหัสผ่าน | bcrypt (`BCryptSHA256PasswordHasher` ของ Django) |
| Cache | Django cache แบบหน่วยความจำ (`LocMemCache`) ไม่ต้องติดตั้งโปรแกรมเพิ่ม |

frontend กับ backend เป็นเว็บ Django เดียวกัน (same origin) จึงไม่มีปัญหา CORS · รันบนเครื่องตัวเองหรือเซิร์ฟเวอร์ของวิทยาลัย ไม่ได้ใช้ cloud

## ความสามารถหลัก

- บันทึก/แก้ไข/ลบช่องโหว่ (CVE) ผูกกับอุปกรณ์ ระดับความรุนแรง 1-5, CVSS, ประเภท, ผู้รับผิดชอบ และติดตามสถานะ ยังไม่แก้ไข → กำลังแก้ไข → แก้ไขแล้ว พร้อมประวัติทุกครั้ง
- **คะแนนความเสี่ยง (Risk Score) = Likelihood (โอกาสเกิด 1-5) × Impact (ผลกระทบ 1-5) = 1-25** แบ่งระดับ
  **ต่ำ 1-4 · ปานกลาง 5-9 · สูง 10-14 · วิกฤต 15-25** — ในฟอร์มเพิ่ม/แก้ไข ระบบคำนวณคะแนนและระดับให้ทันทีบนเบราว์เซอร์ตอนเลือกค่า
  แสดงในรายการ (คอลัมน์ + กรอง + เรียงตามความเสี่ยง) หน้ารายละเอียด การ์ดบนแดชบอร์ด และไฟล์รายงาน CSV
- แดชบอร์ด: กราฟตามระดับความรุนแรง ตามห้อง แนวโน้ม 6 เดือน รายการเร่งด่วน (ระดับ 5/4 ที่ค้าง) ช่องโหว่ล่าสุด และการ์ด "ระดับความเสี่ยงของช่องโหว่ที่ยังไม่แก้ไข"
  ตัวเลขอัปเดตทุกครั้งที่โหลด/รีเฟรชหน้า (เรนเดอร์ฝั่งเซิร์ฟเวอร์ ไม่ได้ push แบบ real-time)
- **Cache ตัวเลขสรุปบนแดชบอร์ด 5 นาที** — คีย์ cache ผูกกับจำนวนและเวลาแก้ไขล่าสุดของช่องโหว่/อุปกรณ์ เมื่อมีการเพิ่ม แก้ไข ลบ เปลี่ยนสถานะ หรือนำเข้าไฟล์ ตัวเลขจะรีเฟรชทันที (ตัวเลขเฉพาะของแต่ละคน เช่น "งานของฉัน" ไม่ถูก cache)
- นำเข้าผลสแกน CSV/JSON (รองรับคอลัมน์ `likelihood`, `impact` แบบไม่บังคับ), รายงานสรุป + ดาวน์โหลด CSV (เปิดใน Excel ภาษาไทยไม่เพี้ยน) / พิมพ์ PDF
- สิทธิ์ตามบทบาท 3 บทบาท + สิทธิ์ระดับรายการ, **รหัสผ่านเข้ารหัสด้วย bcrypt**

## วิธีติดตั้งและรัน

```bat
git clone https://github.com/tang1811/VulnTrack.git
cd VulnTrack
```

### แบบง่าย (Windows) — ดับเบิลคลิก

1. ติดตั้ง Python 3.12 ขึ้นไป จาก https://www.python.org/downloads/ (ติ๊ก **Add python.exe to PATH**)
2. **ดับเบิลคลิก `run.bat` ได้เลย** — ครั้งแรกจะเรียก `setup.bat` ให้อัตโนมัติ (สร้าง `.venv`, ติดตั้งไลบรารีรวมถึง bcrypt, สร้างฐานข้อมูล, ใส่ข้อมูลตัวอย่าง ต้องต่ออินเทอร์เน็ต)
   แล้วเปิดเว็บและเบราว์เซอร์ที่ http://127.0.0.1:8000 ให้ (ปิดเว็บด้วย Ctrl+C หรือปิดหน้าต่าง)
3. ครั้งต่อไปดับเบิลคลิก `run.bat` อย่างเดียว ทุกครั้งที่เปิด `run.bat` จะรัน `migrate` ให้ก่อน ตารางที่เพิ่มใหม่ (เช่น migration `0003` ของ Likelihood/Impact) จึงอัปเดตเอง

`setup.bat` ยังดับเบิลคลิกเองได้ เช่น หลังแก้ `requirements.txt` (`run.bat` เรียก setup ให้เฉพาะตอนยังไม่มี `.venv`) · เวลาย้ายโฟลเดอร์หรือคัดลอกไปเครื่องอื่น ไม่ต้องเอา `.venv` ไปด้วย

### แบบพิมพ์คำสั่งเอง

```bash
python -m venv .venv
.venv\Scripts\activate            # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt

python manage.py migrate
python manage.py seed_demo         # สร้างข้อมูลตัวอย่าง
python manage.py runserver
```

เปิด http://127.0.0.1:8000 แล้วล็อกอินด้วยบัญชีทดลอง (รหัสผ่านทุกบัญชี `Eec@2569demo`)

| ชื่อผู้ใช้ | บทบาท |
|---|---|
| `admin` | ผู้ดูแลระบบ |
| `tech1`, `tech2` | เจ้าหน้าที่เทคนิค |
| `exec` | ผู้บริหาร |

ถ้าต้องการล้างข้อมูลแล้วสร้างใหม่: `python manage.py seed_demo --reset`

> **ฐานข้อมูลตัวอย่างที่สร้างไว้ก่อนอัปเดตนี้** จะไม่มีค่า Likelihood/Impact ช่องโหว่เดิมจึงแสดงความเสี่ยงเป็น "ยังไม่ประเมิน"
> (แก้ไขทีละรายการเพื่อใส่ค่าได้) ถ้าอยากได้ข้อมูลตัวอย่างที่มีคะแนนความเสี่ยงครบ ให้รัน
> `.venv\Scripts\python manage.py seed_demo --reset` — **คำเตือน: `--reset` ลบข้อมูลเดิมทั้งหมด** (ช่องโหว่ อุปกรณ์ ประวัติ และบัญชีตัวอย่าง) แล้วสร้างใหม่ อย่าใช้กับฐานข้อมูลที่มีข้อมูลจริง

### ใช้ MySQL

1. สร้างฐานข้อมูลที่รองรับภาษาไทย
   ```sql
   CREATE DATABASE eec_vulntrack CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   ```
2. คัดลอก `.env.example` เป็น `.env` แล้วใส่ `DB_ENGINE=mysql` กับรหัสผ่าน MySQL
3. รัน `python manage.py migrate` และ `python manage.py seed_demo`

ถ้าไม่มีไฟล์ `.env` หรือไม่ได้ตั้ง `DB_ENGINE=mysql` ระบบจะใช้ SQLite (`db.sqlite3`) ให้ทดลองได้ทันที

## สิทธิ์ของแต่ละบทบาท

เมนูและปุ่มที่ผู้ใช้ไม่มีสิทธิ์จะ **ไม่แสดง** และถ้าพิมพ์ URL เข้าไปตรง ๆ จะได้หน้า 403 (ตรวจสิทธิ์ฝั่งเซิร์ฟเวอร์ทุกหน้า)

| หน้า / การทำงาน | ผู้ดูแลระบบ | เจ้าหน้าที่เทคนิค | ผู้บริหาร |
|---|:-:|:-:|:-:|
| แดชบอร์ดภาพรวม | ✓ | ✓ | ✓ (ดูอย่างเดียว) |
| ดูรายการ/รายละเอียดช่องโหว่ | ✓ | ✓ | – |
| เพิ่มช่องโหว่ | ✓ | ✓ (เป็นผู้รับผิดชอบเองอัตโนมัติ) | – |
| แก้ไขช่องโหว่ และเปลี่ยนสถานะ | ✓ ทุกรายการ | ✓ เฉพาะงานของตัวเอง หรืองานที่ยังไม่มีผู้รับผิดชอบ | – |
| มอบหมาย/เปลี่ยนผู้รับผิดชอบให้ผู้อื่น | ✓ | – (รับงานว่าง / คืนงานของตัวเองได้) | – |
| ลบช่องโหว่ | ✓ | – | – |
| ดูข้อมูลอุปกรณ์ | ✓ | ✓ | – |
| เพิ่ม/แก้ไข/ลบอุปกรณ์ | ✓ | – | – |
| นำเข้าไฟล์ผลสแกน CSV/JSON | ✓ | ✓ | – |
| รายงานสรุป + ดาวน์โหลด CSV / พิมพ์ PDF | ✓ | – | ✓ |
| ประวัติการเปลี่ยนสถานะทั้งระบบ | ✓ | – | – |
| จัดการผู้ใช้ | ✓ | – | – |
| จัดการประเภทช่องโหว่ | ✓ | – | – |

ตารางสิทธิ์อยู่ที่ไฟล์เดียวคือ `accounts/roles.py` แก้ที่นี่แล้วเมนู ปุ่ม และการตรวจสิทธิ์จะเปลี่ยนตามทั้งหมด

**สิทธิ์ระดับรายการ (`can_work_on`)** — นอกจากสิทธิ์ตามบทบาทแล้ว เจ้าหน้าที่เทคนิคแก้ไข/เปลี่ยนสถานะได้เฉพาะช่องโหว่ที่มอบหมายให้ตัวเอง
หรือที่ยังไม่มีผู้รับผิดชอบ (กด "เริ่มแก้ไข" แล้วระบบตั้งให้เป็นผู้รับผิดชอบทันที) ระบบตรวจซ้ำหลังล็อกแถวข้อมูล
จึงกันกรณีที่ผู้ดูแลมอบหมายงานให้คนอื่นระหว่างที่อีกคนเปิดหน้าค้างไว้ได้ ผู้ดูแลระบบทำได้ทุกรายการ

**ผู้รับผิดชอบ / ผู้แก้ไข** — ผู้รับผิดชอบคือคนที่ได้รับมอบหมาย ผู้แก้ไขคือคนที่เปลี่ยนสถานะเป็น "แก้ไขแล้ว" (ระบบบันทึกเอง
ถ้าเปิดกลับเป็นยังไม่แก้ไขจะล้างค่า) การมอบหมายทุกครั้งบันทึกลงประวัติพร้อมชื่อผู้มอบหมาย

```
tracker/           ระบบหลัก
  models.py          Asset, Vulnerability, StatusHistory, ImportLog
  services.py        เปลี่ยนสถานะพร้อมบันทึกประวัติ, นำเข้าไฟล์สแกน
  views.py           ทุกหน้า (dashboard, ช่องโหว่, อุปกรณ์, นำเข้า, รายงาน, ประวัติ)
  management/commands/seed_demo.py   ข้อมูลตัวอย่าง

static/            CSS (Design System), JavaScript (กราฟ), Chart.js
```

## ฐานข้อมูล (5 ตาราง)

| ตาราง | เก็บอะไร |
|---|---|
| `accounts_user` | ผู้ใช้และบทบาท (admin / technician / executive) |
| `tracker_asset` | อุปกรณ์: hostname, IP, ประเภท, ระบบปฏิบัติการ, ห้อง, ผู้รับผิดชอบ |
| `tracker_vulnerability` | ช่องโหว่ 1 แถว = CVE 1 ตัวบนอุปกรณ์ 1 เครื่อง: ระดับความรุนแรง, CVSS, Likelihood, Impact, สถานะ, วันที่พบ/แก้ไข (คะแนนความเสี่ยงคำนวณจาก Likelihood × Impact ไม่ได้เก็บแยก) |
| `tracker_statushistory` | ประวัติการเปลี่ยนสถานะ: จากสถานะ → เป็นสถานะ, ผู้เปลี่ยน, เวลา, หมายเหตุ |
| `tracker_importlog` | บันทึกการนำเข้าไฟล์ผลสแกน |

สถานะช่องโหว่: **ยังไม่แก้ไข (open) → กำลังแก้ไข (in_progress) → แก้ไขแล้ว (fixed)**

## การรักษาความปลอดภัยที่ทำไว้

- ทุกหน้าต้องล็อกอิน (`LoginRequiredMiddleware`) และตรวจสิทธิ์ตามบทบาททุกหน้า
- รหัสผ่านเข้ารหัสด้วย **bcrypt** (`BCryptSHA256PasswordHasher` เป็นค่าหลักใน `PASSWORD_HASHERS`) บัญชีเดิมที่เป็น PBKDF2 ยังล็อกอินได้ และระบบเปลี่ยนเป็น bcrypt ให้เองเมื่อล็อกอินครั้งถัดไป
- ตรวจความแข็งแรงของรหัสผ่าน (อย่างน้อย 8 ตัว ไม่ใช่ตัวเลขล้วน ไม่ใช่รหัสที่พบบ่อย)
- ล็อกอินแบบ session ของ Django (คุกกี้ HttpOnly หมดอายุเมื่อปิดเบราว์เซอร์หรือครบ 8 ชั่วโมง) เมื่อ `DEBUG=False` เปิด `SESSION_COOKIE_SECURE` / `CSRF_COOKIE_SECURE` สำหรับใช้ผ่าน HTTPS
- ป้องกัน CSRF ทุกฟอร์ม, SQL Injection (ใช้ ORM ที่ส่งค่าแบบ parameterized), XSS (template escape อัตโนมัติ เช่น `<script>` กลายเป็น `&lt;script&gt;`), Clickjacking
- ตรวจข้อมูลในฟอร์ม: รูปแบบ CVE, CVSS 0-10, วันที่พบห้ามเป็นอนาคต, Likelihood/Impact 1-5
- การเปลี่ยนสถานะรับเฉพาะ POST และกัน open redirect
- ไฟล์นำเข้า: รับเฉพาะ .csv/.json ขนาดไม่เกิน 2 MB ตรวจรูปแบบทุกแถว
- ผู้ดูแลระบบลดสิทธิ์หรือปิดบัญชีตัวเองไม่ได้
- ข้อมูลลับอยู่ใน `.env` (ไม่ commit) — ก่อนใช้งานจริงต้องตั้ง `SECRET_KEY` ใหม่และ `DEBUG=False`

## ข้อมูลตัวอย่าง

รหัส CVE ชื่อ และคะแนน CVSS เป็นข้อมูลจริงจาก NVD ส่วนชื่ออุปกรณ์ ห้อง ผู้ใช้ และสถานะการแก้ไขเป็นข้อมูลสมมติ
